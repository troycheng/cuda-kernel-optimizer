# 跨架构诊断资料检查

## Case Snapshot

公开基线 `f023988` 的异步搬运卡合并了 cp.async/TMA，若干流水线卡以固定 stall 或 bank-conflict 阈值替代原因区分。通信卡已有 rank 等待诊断，但缺少实际拓扑、消息大小和重叠的联系。这是资料内容缺口，不是已复现的 H800 性能失败。

修订范围为七张现有卡片、相关来源、兼容性与环境参考，以及一份按需读取的 Hopper 说明。保持 97 张卡；SKILL、Python、schema、执行接口和运行流程不变。没有私有材料或 GPU 测量。

## Evaluation Definition

以首次包含本文件的提交固定候选及以下题设，结果在后续提交记录。只评估修订版，不做旧版对照，不宣称模型能力提升。一次全套 CPU 测试、self_check、skill quick_validate、跨架构检索检查，以及一次独立只读语义检查；不新增测试框架或 GPU workload。

独立评阅使用空白上下文的 gpt-6.1-sol、medium 推理；精确后端快照与 token 数若不可取得则记未知。提供本次修改文件清单和下面六题，不提供父会话答案或预期结论。只读当前代码、资料及题设，不运行网络、GPU、基准或写操作。每题回答可支持的判断、最低成本下一步或无需行动、不能推出的结论。不同合理路径均可接受。

题设均为公开合成情境，不是实测数据：

1. H800，Tensor Core 活跃率低，dispatch 已确认；问题只产生少量 CTA，每个 CTA 时间很短，无搬运/计算等待细分。提出下一步。
2. 同为 H800，但 grid 充足；已有阶段观测显示 consumer 等待数据，producer 持续拷贝。另有地址映射不合并的证据；没有 stage 增加后的资源数据。提出下一步。
3. A100 的生成代码已有 global-to-shared cp.async。有人据此准备直接使用一个 Hopper TMA/WGMMA 模板。评估依据及下一步。
4. 另一台 SM120 GPU 可以编译相应功能；候选照搬 H100 的 tile/stage，现有编译报告显示共享内存增加、驻留 CTA 减少，尚无候选性能结果。评估能得出什么。
5. H800 多卡 collective 区间长；对齐时间线显示一个 rank 的上游计算晚到，其他 rank 提前进入 collective。没有更细的传输服务数据。提出下一步。
6. H800 多卡 rank 到达接近；设备对 P2P 可达，但实际消息大小、GPU—NIC 映射和传输吞吐未知；离线，当前资料不足以确认 backend 版本能力。提出下一步。

验收按因果区分、适用条件、不确定性和检查成本判断；不能因单指标选定机制，不能从硬件身份推定编译/dispatch，不能把缺资料当作无方向。发现内容错误可修正，但保留初次结果，不反复追加题目追求通过。接口检查只证明检索、来源和链接可用；单轮语义检查不证明泛化、效率或性能收益。GPU/驱动/CUDA 对该只读评阅不适用。

## Evaluation Result

定义及候选固定在 `fcb54e0`，2026-11-04 完成检查，候选内容未在评测后调整。

- CPU 全套测试：`python3 -m unittest discover -s tests -p 'test_*.py'`，255 项，2 项环境相关跳过，其余通过，46.211 秒，退出码 0。
- `self_check.py`、compileall、diff whitespace 检查退出码均为 0。系统 Python 的 quick_validate 首次因缺 PyYAML 未执行；改用 `uv run --no-project --with PyYAML` 的隔离环境后通过，退出码 0，没有修改项目依赖或全局 Python。
- 调用现有 query 接口：SM80/90/100/120 均能取到通用 producer/consumer 材料及摘要绑定的文档路径，每次 1824 bytes；这是资料匹配，不是相同指令支持声明。H800、TMA 能发现说明，NVLink 与中文“多卡通信”能发现通信卡；SM80 显式查询 TMA 保留不匹配说明，未知机制仍正常返回空结果。
- 独立子智能体 `cross_architecture_review`，请求配置 gpt-6.1-sol / medium，一轮只读、无网络或 GPU；未取得精确后端快照、token 用量及独立耗时，记为未知。未发现阻塞问题或新增强制流程。

六题的语义结果：1 区分工作量不足，不从低利用率推定 TMA 收益；2 优先检查已有地址映射问题，不把 producer 忙等同带宽饱和；3 不把 A100 cp.async 当作 Hopper 模板可用的证据；4 承认资源代价，但不从驻留下降断言必然更慢；5 先查迟到 rank 上游，不把 collective 总区间当传输时间；6 先补消息与映射资料，仅在传输仍是关键未知时测相关路径，离线版本能力保持未知。

全部计划内检查已完成，没有追加题目或重复调参。只支持资料自洽、接口可用及上述六个情境的合理解释，不证明相比旧版准确率、token 效率或 H800 性能提高。没有 GPU 调用或私有材料。卡片仍为 97 张，cards.json 为 199979 bytes；生产 Python、schema、SKILL 和现有测试文件均未修改。
