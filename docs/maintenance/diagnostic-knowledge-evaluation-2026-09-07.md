# 三张诊断卡的定向检查

## Case Snapshot

来源是公开知识卡及 CUDA Best Practices 13.3 的 Coalesced Access、Occupancy / Thread and Block Heuristics，以及 NCU Profiling Guide 的 Memory Tables、SASS 动态计数定义。旧卡将单个指标作为区分问题；这是可直接检查的内容缺口，不声称复现私有任务的失败。

挑战为六个合成情境，三个主题各有反例；不是 GPU 测量。访存：SM80、32 个活跃 lane、float32、32-byte 对齐，分别连续地址/4 sectors/5% hit 与 stride 128 bytes/32 sectors/95% hit。寄存器：大 grid，分别无 spill、有 ILP 且降寄存器候选 10→12 us；与 hot loop 存在 spill 但无候选性能证据。指令：分别二进制有 tensor 指令但 dispatch 不匹配；与匹配 kernel 动态计数为正但成对性能无变化。

共同请求：对每个情境给出可支持的判断、最低成本下一步或无需行动、不能成立的结论；不得执行实验、搜索或修改文件。完整挑战在评测时固定于 `/tmp/cko-diagnostic-challenge.md`，以上数值均为合成题设。没有私有材料。

## Evaluation Definition

基线 main `959c1ba` 的三张卡与本次改写三张卡分别作为独立阅读材料；不暴露另一组或参考答案。卡片集合 SHA256：before `a4fdaaa06f22530aeff837e7c0b773dc278691121032e906b7a4738cab416af0`；after `78764125a49dbc155a2747db23341ae49664c59013ad9864507a72de39b67b71`。来源、模型配置、题设与授权相同，唯一比较轴为卡片内容。

两次独立空白上下文子智能体，各一轮六题，继承当前模型和思考设置，不显式覆盖。后端精确模型快照不可固定；不测服务或 GPU 性能。允许只读两份指定文件，总回答限 650 words；不增加重复轮次挑选结果。

检查是否区分访存与缓存、驻留与 spill、静态存在与动态执行/收益，是否提出与缺口对应的便宜动作。多条合理路径均可接受；缺失证据应保持未知。额外工具调用、耗时可记录，若 token 用量未暴露则标未知。单轮无显著性结论，两个版本都答对意味着没有证明改写提高模型能力。

该定义在结果产生前固定；本地工作树尚未提交，因此这只是定向检查，发布前如需正式演进验收，应先提交定义再独立执行，不能将本结果称为预注册发布评测。

## Evaluation Result

2026-09-07 完成。两个空白上下文子智能体 `diagnostic_before`、`diagnostic_after` 使用相同继承配置，各一次读取指定卡片与挑战后作答，无网络、GPU 或写操作。token 用量及精确模型快照、可比的独立推理耗时未暴露，标为未知，不估算节省比例。

| 题组 | before | after |
|---|---|---|
| 1A/1B | 连续读取已合并，不因低命中率向量化；跨 lane 分散时查映射，不从高命中率推定高效 | 同样区分，明确计入布局转换成本 |
| 2A/2B | 拒绝更慢的低寄存器候选；spill 只支持调查 live range，不宣称已有收益 | 同样区分，并指出不能将 2A 的全部退化严格归因于指令数 |
| 3A/3B | 静态存在不能证明 dispatch；动态计数仅证明执行，无速度收益 | 同样区分，不增加新实验 |

两组均在六个情境中给出合理判断和有界下一步；没有发现需要修订卡片的新反例。两组各一次只读工具调用，其余工具调用、GPU 调用均为零。旧卡组也能凭模型知识纠正指标暗示，因此没有证明改写提升准确率、效率或泛化。该检查只覆盖独立卡片阅读，不覆盖完整优化任务或检索排序质量。

确定性验证：13 项 knowledge_query 测试通过；全套 253 项测试运行 47.813 秒，2 项环境相关跳过，其余通过；self_check、quick_validate、diff whitespace 检查通过。四种架构输入 SM80/90/100/120 均返回三张建议卡，6320 bytes，空查询正常完成。这证明通用诊断材料可以返回，不证明这些 GPU 支持相同指令。没有修改生产 Python 或测试。

执行中体积测试曾拒绝过长文案，随后只压缩三张卡的重复内容，未放宽 200000-byte 上限；最终 cards.json 为 199893 bytes、97 张卡。一次临时查询脚本误读 `applicability.status`（实际字段为 `relation`），修正临时读取后通过，未改生产接口。
