# V1.3 知识增强分析引擎实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用
> `superpowers-zh:subagent-driven-development` 逐任务实现本计划。每项任务先写失败测试，
> 再写最小实现；一个任务只由一个实现代理修改，完成后再进行规格和代码审查。

**目标：** 在不改变 V1.2 投入控制、授权和候选状态机的前提下，用受身份约束的本地知识和
稳定 profile 观测，更早提出最多三个可证伪的性能机制，并在冻结的真实 Triton 决策点上证明
方向命中或证据成本优于 V1.2。

**架构：** `diagnostic_knowledge.py` 是唯一检索真相，暴露纯函数
`build_knowledge_context(frozen_inputs)`；它统一归一化两类已封存证据，完成内容校验、身份过滤、
机制去重、Pareto 筛选和 12 KiB 输出约束。`knowledge_query.py` 只做输入输出适配，
`workload_controller.py` 只在既有上下文构建、证据刷新和候选适配接点调用该纯函数。

**技术栈：** Python 3 标准库、JSON、`unittest`、现有 V1.2 Controller 和内容寻址产物。
所有自动化验证均为离线 CPU 测试，不调用 GPU、网络或外部 AI。

## 2. 子智能体与验证安排

| 工作 | 模型与强度 | 原因 |
|---|---|---|
| 回放夹具、内容目录、机械校验 | 日常模型，中等思考 | 输入闭合，主要是证据整理和确定性测试 |
| 观测归一化、纯检索实现 | 日常模型，高思考 | 需要保持数据契约一致，但不触碰 Controller |
| Controller 窄接入 | 强代码模型，高思考 | 涉及现有事务、恢复和状态绑定，错误代价最高 |
| 每阶段规格审查 | 与实现代理不同的强代码模型，中等思考 | 只对照设计和 diff，不重复探索代码 |
| 最终整体审查 | 强代码模型，高思考 | 检查跨任务接口、冻结边界和回放结论 |

实现任务串行执行。只读的证据盘点和测试范围审查可以并行；不同代理不得同时修改
`diagnostic_knowledge.py` 或 `workload_controller.py`。主代理负责提交、远端操作和最终结论。

## 3. 实现前固定的五项契约

### 3.1 知识身份

`knowledge_identity` 由 `_build_active_diagnosis_context()` 写入正式
`diagnosis_context.json`。它只读取：

- readiness report result 的 contained `evidence_path`；
- probe 同目录、同 requirement id 的 `.complete.json` 和 `.execution.json`；
- 冻结 analysis contract 中的 profiler 名称和版本；
- 当前 analysis epoch 的 workload、source、environment identity digest。

readiness 链固定为：

```text
report result.evidence_path
  -> <requirement>.json
  -> sibling <requirement>.complete.json
  -> marker.probe_sha256 == sha256(probe bytes)
  -> marker.execution_sha256 == sha256(<requirement>.execution.json bytes)
  -> execution.environment_identity_digest == result.identity_digest
```

所有路径必须位于 run root，三个文件必须是普通文件，marker schema 必须是
`cuda-workload-optimizer/readiness-completion-v1`，requirement id 必须一致。
身份字段的 `source_sha256` 使用 marker 绑定的 `probe_sha256`。

字段采用统一事实结构：

```json
{
  "schema_version": "cuda-optimizer/knowledge-identity-v1",
  "gpu_architecture": {
    "value": "sm_120",
    "status": "verified",
    "source_kind": "readiness_probe",
    "source_sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
  },
  "driver_version": {
    "value": null,
    "status": "unknown",
    "source_kind": "unknown",
    "source_sha256": null
  },
  "cuda_runtime_version": {
    "value": null,
    "status": "unknown",
    "source_kind": "unknown",
    "source_sha256": null
  },
  "framework_versions": {},
  "compiler_versions": {},
  "profiler_versions": {
    "nsys": {
      "value": "2026.3",
      "status": "verified",
      "source_kind": "analysis_contract",
      "source_sha256": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb"
    }
  },
  "workload_contract_sha256": "cccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccc",
  "source_sha256": "dddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddddd",
  "environment_sha256": "eeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeeee"
}
```

readiness probe 仅识别白名单字段：`sm_arch`、`driver_version`、`cuda_runtime_version`、
`framework_versions`、`compiler_versions`、`profiler_versions`。缺失或冲突字段固定为
`unknown`；构建上下文时不重新探测机器，也不读取 adapter id/version 充当平台身份。

### 3.2 Active evidence 的稳定观测

现有 `evidence_result.observations` 仍允许项目自定义 JSON。V1.3 只识别其中闭合的
`semantic_observations` 数组：

```json
{
  "semantic_observations": [
    {
      "semantic_id": "runtime.launch_gap_us",
      "status": "observed",
      "value": 12.5,
      "unit": "us",
      "scope": ["cpu-submit", "gpu-kernel"],
      "aggregation": "median",
      "tool": {"name": "nsys", "version": "2026.3"},
      "quality": "validated"
    }
  ]
}
```

未知字段继续保留在原始证据中，但不参与知识检索。缺单位、scope、aggregation、tool version
或 quality 的数值不得补猜，只记录为未形成稳定观测。`ERR_NVGPUCTRPERM` 仅规范为
`profile.counter_access=unavailable`。

### 3.3 知识上下文输出

`build_knowledge_context()` 返回闭合结构：

```text
schema_version
input_sha256
knowledge_package: {version, sha256}
knowledge_identity_sha256
evidence_sha256
performance_model_sha256
categories
candidates
explanations
rejections
filtered_counts
promotion_authority
```

每个 candidate 必须含 `mechanism_key`、`statement`、`execution_layers`、`scope_node_ids`、
`evidence_grade`、支持/反向/缺失观测、`benefit_ceiling` 的 performance model 引用、
`cheapest_falsifier`、`source_ids`、`case_ids`、`confidence: inconclusive` 和
`promotion_authority: none`。输出摘要必须随任一正式输入或知识包摘要变化。

### 3.4 查询兼容策略

`knowledge_query.py` 增加 `--frozen-input FILE` 和 `query_frozen()`，两者只委托
`build_knowledge_context()`。现有 `query(arch, layer, axis, bottleneck, observed_metrics,
limit)` 保留为兼容的“方法目录查询”，返回结构不变，但不得被 Controller、机制候选或发布回放
调用。V1.3 不用旧参数伪造 execution map、performance model 或 readiness。

### 3.5 回放指标

只有通过 3.6 回放资格门禁的案例才保存 V1.2 baseline。baseline 保存可计算字段，而不只保存
输出摘要：

```text
ranked_mechanism_keys
next_actions: [{action_id, cost_class, is_profiler, measured_seconds}]
decision
valid_for_scoring
route_output_sha256
```

标签保存 `accepted_mechanism_keys`、`cheapest_valid_action_ids`、
`expected_terminal_decisions` 和来源摘要。Top-1/Top-3、有效方向前 action 数和成本、
profiler 数、终态和身份误复用全部由测试现场计算。知识候选不能直接产生 `PURSUE`；
“错误 PURSUE 不增加”由知识候选保持 `inconclusive` 的契约测试和未修改的
hypothesis/evidence/diagnostic-decision 链联合证明。

### 3.6 回放资格

历史记录不能为了适配当前 `execution_map` 契约而补造时序。每个案例先写：

```json
{
  "replay_eligibility": {
    "status": "scoreable | partial | rejection_only",
    "reason_codes": ["missing_execution_window"],
    "timing_provenance": [
      {
        "target": "execution_map.nodes[0].duration_us",
        "relative_path": "analysis.json",
        "source_sha256": "<真实摘要>",
        "locator": "/views/baseline/target_kernel_rows/0/mean_ns",
        "source_value": 2049.87,
        "source_unit": "ns",
        "transform": "divide_by_1000"
      }
    ]
  }
}
```

`scoreable` 要求 identity、epoch、map 和 model 的全部事实能从决策前输入逐字段追溯；
`partial` 不得含 execution map、performance model 或排名 baseline；
`rejection_only` 只验证缺证据、身份失配或测量无效时 fail closed。允许的派生仅限记录完整来源的
确定性单位换算、筛选和坐标平移；聚合差值不能被解释为节点持续时间，单个 span 不能被展开为
未观测的拓扑、coverage、occurrences 或起止时间。

- [ ] **步骤 3：编写回放完整性和指标基线测试**

`tests/test_knowledge_replay.py` 至少包含：

```python
def test_frozen_inputs_do_not_contain_future_labels(self):
    forbidden = {"accepted_mechanism_keys", "cheapest_valid_action_ids",
                 "expected_terminal_decisions", "label_source_sha256",
                 "speedup", "verdict"}

    def keys(value):
        if isinstance(value, dict):
            return set(value).union(*(keys(item) for item in value.values()))
        if isinstance(value, list):
            return set().union(*(keys(item) for item in value))
        return set()
```

## 5. 停止条件

出现以下任一情况时停止扩展并回到整体设计：

- 需要修改 V1.2 决策状态、grant、promotion 或恢复语义；
- 需要新增第二套检索排序、profile 执行协议或知识 schema 体系；
- 真实回放只能靠未来证据、历史收益数字或无效压测才能改善；
- Controller 无法在既有 diagnosis/evidence 事务中保持 context 唯一正式值；
- 定向测试需要大量按卡片或 profiler 字段枚举才能通过。

这五项不是延后处理清单，而是判断当前实现路径错误的信号。
