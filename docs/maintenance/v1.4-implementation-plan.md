# V1.4 实施计划

本文把《V1.4 架构规格：模型决策，工具执行》落实为可执行的修改顺序。架构规格定义产品行为；
本文只定义如何迁移、如何测试以及何时停止，不增加新的产品概念。

## 1. 实施目标

V1.4 只完成一件事：

> ChatGPT 负责分析、选择方向和决定投入；代码只执行一次明确操作并保存可核验结果。

实施完成后：

- 不再存在 Controller、Orchestrator、全局优化状态、预算决策器或自动下一步；
- command driver 是唯一 workload 执行入口；
- 一次公开调用只完成一个 `operation`；
- 目标、候选实验、调用结果和最佳版本选择都是不可变记录；
- 长任务由独立 guardian 监督，断连、超时和取消不会遗留本机进程；
- 生产 Python 从当前 63 个文件、54,999 行收敛到不超过 17 个文件，并显著减少总行数；
- 不提供旧入口兼容层。

## 2. 已冻结的实现决定

以下决定在编码时不得重新讨论或变形：

1. ChatGPT 是唯一优化决策者。工具不生成方向、ROI、下一步或继续/停止建议。
2. 没有中央执行器。公开工具之间不会互相调用。
3. 没有全局流程状态。`Invocation` 只表示一次操作，不表示任务阶段。
4. workload 只通过独立 command driver 运行。现有 Python adapter 动态导入路径删除。
5. `benchmark.py` 的 CUDA/CUTLASS/Triton 构建和测量主线不迁入评估器。用户项目如需这些能力，
   由自己的 driver 调用原始入口。
6. 工具不自动采用候选。`champion.py select` 只记录 ChatGPT 已经做出的选择。
7. Profiler 只输出事实，不解释瓶颈。
8. 知识库没有匹配是正常空结果，不阻止源码分析、第一性原理推理或外部检索。
9. 运行底座不读取 Target、Experiment 或 Champion 的业务含义。
10. 不新增通用 Action schema、Controller 同义文件或旧协议兼容代码。

若实现要求违反任一决定，立即停止该批次；先检查实现是否选错边界，不以“代码不好接”为理由
修改核心模型。

## 3. 最终调用面

所有公开命令采用：

```text
python3 <tool>.py <operation> --request <request.json> [--wait]
```

stdout 只输出一个 JSON 对象。错误写入 stderr，退出码非零。

| 文件 | 公开 operation |
|---|---|
| `readiness.py` | `check` |
| `workload_evaluate.py` | `baseline`、`experiment`、`screen`、`target`、`final_audit`、`status`、`cancel` |
| `profile_ncu.py` | `analyze`、`collect`、`status`、`cancel` |
| `profile_nsys.py` | `analyze`、`collect`、`status`、`cancel` |
| `profile_pytorch.py` | `analyze`、`collect`、`status`、`cancel` |
| `compiler_evidence.py` | `analyze`、`status`、`cancel` |
| `sass_check.py` | `analyze`、`status`、`cancel` |
| `knowledge_query.py` | `query` |
| `champion.py` | `show`、`select`、`restore-original` |
| `self_check.py` | 安装面检查 |

`_invocation_runtime.py` 没有公开优化 operation。它的 guardian 和 worker 模式是工具内部实现，
不会写入 SKILL、README 或公开帮助。

### 3.1 Operation input 与冻结 request

`--request` 接受 operation input。调用方只声明要做什么和本次允许使用的资源、采样与安全
限制；所属工具补齐不能由调用方控制的内容后，才写入 Invocation 的 `request.json`。

所有长任务 operation input 共有：

```text
format_version
operation
artifact_root
target_ref
sampling_design              # 该 operation 适用时
resources
operation_timeout_seconds
command_timeout_seconds
resource_wait_timeout_seconds
cleanup_timeout_seconds
launch_deadline
absolute_deadline             # 可选
retry_of                      # 可选
```

具体 operation 只增加：

| operation | 调用方增加的字段 | 工具从不可变记录补齐 |
|---|---|---|
| `baseline` | 无 | original Variant、driver、cleanup |
| `screen` | `experiment_ref` | candidate、reference、screen design、driver、cleanup |
| `target` | `experiment_ref` | candidate、当前 reference、screen receipt、driver、cleanup |
| `final_audit` | 无 | original、当前 Champion、Selection、driver、cleanup |
| Profiler `analyze` | `report_ref` | 报告内容、环境和可选 candidate binding |
| Profiler `collect` | `role`、candidate 时的 `experiment_ref` 和 `correctness_ref` | Variant、driver、profiler wrapper、cleanup |
| 编译器/SASS `analyze` | `artifact_ref` | 产物、环境和可选 candidate binding |

工具计算并写入 `variant_refs`、`selection_ref`、`cleanup`、`tool_identity` 和
`request_digest`。operation input 出现这些工具所有字段时按未知字段拒绝。

同步 operation input：

| operation | 必填内容 |
|---|---|
| readiness `check` | 新 artifact root、目标模式、结论层级、测试集、精度、original、目标指标、driver、环境要求、有效性要求、smoke 与扫描上限 |
| evaluator `experiment` | Target 与 baseline reference、source base、candidate、假设、机制、结论层级、falsifier、screen design、成本范围、收益阈值、拒绝/通过条件、修改范围与最高风险 |
| knowledge `query` | Target reference，或完整硬件、软件、现象和结论层级身份；过滤条件与输出上限 |
| Champion `show` | artifact root 和 Target reference |
| Champion `select` | Target reference、普通 target result reference、预期当前 Selection |
| Champion `restore-original` | Target reference、final audit result reference、预期当前 Selection |
| `status`、`cancel` | artifact root 和 invocation id |

`format_version` 只标识所属工具的输入格式，不形成通用 Action schema。

## 4. 最终模块与函数归属

下面固定每项能力的唯一归属。函数名允许在实现时做小幅命名调整，但职责和依赖方向不能改变。

### 4.1 `artifact_store.py`

保留并收敛：

- 安全读取普通文件；
- `create-once`、原子替换和原子发布一组文件；
- append-only 事件；
- 内容摘要；
- 有界目录快照、内容寻址对象和隔离物化；
- record reference 校验；
- Champion current reference 的 compare-and-swap。

建议内部接口：

```text
canonical_json_bytes(value)
sha256_bytes(value)
sha256_file(path)
read_bytes(path)
read_json(path)
create_json(path, value)
replace_json(path, value)
publish_bundle(directory, writes, removals)
append_jsonl(path, value)
freeze_path(artifact_root, source, scan_limits)
materialize_object(artifact_root, object_ref, destination)
validate_record_ref(artifact_root, record_ref, expected_type)
compare_and_swap_ref(artifact_root, relative_path, expected_digest, replacement)
```

不保留 checkpoint、stage、预算、下一步、全局 ledger 或旧 `ArtifactStore` 中只服务旧流程的方法。

### 4.2 `_invocation_runtime.py`

唯一职责是可靠运行一项已校验调用：

```text
probe(command_spec, runtime_limits, resources)
submit(artifact_root, frozen_request, worker_argv, wait)
wait(artifact_root, invocation_id)
status(artifact_root, invocation_id)
cancel(artifact_root, invocation_id)
run_child(command_spec)
check_cancelled()
```

实现固定为：

1. 公开工具前台完成业务校验并生成冻结 request；
2. runtime 按 `request_digest` 使用确定性 invocation id 合并完全相同的普通请求；
3. runtime 启动一个独立 guardian；
4. guardian 先建立启动闸门，再创建所属工具的语义 worker；
5. worker 通过两条继承 pipe 向 guardian 提交结构化子命令；
6. guardian 是 worker 和所有本机子进程的唯一创建者；
7. guardian 在第一次共享资源子命令前，按稳定顺序取得 request 声明的完整资源集合；
8. guardian 监督 launch、资源等待、operation、command、absolute deadline 和 cancel；
9. worker 解释子命令结果并原子写业务 `result.json`；
10. guardian 确认结果已发布且清理完成后退出。

不使用 Unix socket、常驻 daemon、数据库或额外服务。一个 invocation 同时最多运行一个子命令，
这与 workload 的顺序测量模型一致，也避免引入内部调度器。

共享 GPU 锁目录来自安装级配置，默认位于当前账号的固定缓存目录；request 不能覆盖。锁键使用
主机身份和 GPU UUID。多 GPU 请求按键排序后一次持有到 invocation 结束。artifact root 内锁
只保护记录写入，不能代替共享资源锁。

CPU-only 子命令在取得共享资源前运行，环境中隐藏未取得的 GPU。到达 operation、command 或
absolute deadline 后不再启动业务子命令，但 cleanup timeout 仍单独有效。

普通请求的 invocation id 由语义摘要确定。显式 retry 必须引用上一条无有效结果的 invocation；
再次失败时继续引用最近一次 retry。所属工具在提交 retry 前发现已有有效结果时直接返回该结果，
不启动 guardian。tool identity 参与语义摘要；worker 在放行第一个子命令前重新核对实现身份，
执行期间漂移时保留原始材料但把结果标为无效。

前台崩溃、worker 崩溃和 guardian 崩溃分别由启动凭据、进程开始时间、事件和资源占用凭据
判断，不补造业务结果。`status` 可以报告 `worker_lost`，但只有所属工具 worker 能写
`result.json`。guardian 在 worker 的普通执行、资源等待和子命令运行期间按固定间隔追加心跳；
guardian 在 worker 未成功创建时才允许前台形成 `launch_failed`，worker 身份已经存在后不得由
其它进程补造终态。

### 4.3 `workload_adapter.py`

只保留 command driver 协议：

```text
validate_driver(driver)
materialize_target_inputs(artifact_root, workspace, target)
materialize_variant(artifact_root, workspace, variant, name)
build_driver_request(target, variant, role, mode, case, sampling, output_path)
build_argv(driver, driver_request_path)
validate_driver_result(driver_result, expected_request)
```

删除：

- Python 模块动态导入；
- `prepare`、`validate`、`benchmark`、`metrics`、`cleanup` 的进程内调用；
- 子进程启动、输出捕获、timeout 和进程组清理；
- 第二套 workload 身份计算。

driver request/result 是仅有的对外 JSON schema。driver 返回非有限数值、未知单位、身份不匹配
或未确认清理时 fail closed。

V1.4 的 driver 只允许 `cleanup_contract={"kind":"process_group_only","external_tasks":false}`。
driver 及其子任务必须留在 Invocation 进程组内；远端任务、daemonized 服务和脱离进程组的
容器在创建 Target 前拒绝，不在本版本新增第二套外部清理系统。

`validate_driver` 同时冻结 `ncu_wrap_v1`、`nsys_wrap_v1`、
`pytorch_chrome_trace_v1` 三项可选采集能力。driver result 中每项 artifact 使用
`kind`、`relative_path`、`sha256` 三个封闭字段，并在 adapter 内完成无路径逃逸、无符号
链接和内容摘要校验。Profiler 不另建一套 workload 或 artifact 协议。

### 4.4 `readiness.py`

唯一公开动作是同步 `check`：

```text
validate_check_request(request)
inspect_environment(request)
freeze_original_variant(request)
validate_driver(driver)
run_smoke_probe(driver)
build_target(...)
check(request)
```

从旧 readiness 文件中只提取：

- 工具、GPU、驱动、CUDA、Python 和框架身份；
- 安全路径、输入文件和环境清单；
- bounded smoke 的事实采集。

删除旧 readiness state、next actions、remediation workflow 和安装动作。任何失败都发生在
artifact root 原子创建之前。

### 4.5 `workload_evaluate.py`

唯一 workload 测量模块：

```text
baseline(request)
create_experiment(request)
screen(request)
target(request)
final_audit(request)
run_correctness(...)
run_paired_measurement(...)
classify_recorded_pairs(...)
worker_main(invocation)
```

执行器只根据 request 中已经冻结的条件给出测试事实：

- `baseline`：original 正确性通过后才接受性能；
- `experiment`：同步冻结候选、核对当前 reference，不启动命令；
- `screen`：correctness → 可选短版配对测量；
- `target`：两侧正确性 → candidate 与当前 Champion 正式配对；
- `final_audit`：两侧重新检查正确性 → original 与冻结 Champion 直接配对。

`diagnostic_proxy` 只返回其声明主张的结果；代理收益低不自动阻止 target。
`conservative_bound` 只有在预先声明且结果确实形成正式收益上限时，才能得到低于阈值的拒绝
verdict。任何 verdict 都不包含下一项 operation。

保留 `experiment_design.py` 和 `paired_stats.py` 的纯计算；旧 `benchmark.py`、`paired_benchmark.py`
和 `telemetry.py` 只作为结果语义参考，不保留独立执行路径。

### 4.6 `champion.py`

```text
show(request)
select(request)
restore_original(request)
```

`select` 只接受同一 Target、当前 reference 上通过的普通 `target` 结果。它先 create-once 写
Selection，再 CAS 更新 `champion/current.json`。崩溃发生在两步之间时 current 不改变。

`restore-original` 只接受与当前 Selection 绑定、支持恢复的 `final_audit`。它不运行测试，也
不把失败候选替换成另一个候选。

### 4.7 Profiler

三个 Profiler 文件各自实现封闭 dialect：

```text
validate_analyze_request(...)
analyze_report(...)
validate_collect_request(...)
build_collect_argv(...)
collect(...)
worker_main(...)
```

共同的进程能力来自 runtime，共同的 workload argv 来自 adapter，但三者不共享通用
Profiler 基类。未知报告版本、解释测量所需的必需字段或单位使整次分析无效；不能降级成猜测。
已知格式中的非关键扩展字段单独保留为 `unmodeled`，不能静默忽略或参与语义计算。

`profile_ncu.py` 收敛现有 NCU 解析、权限判断和已知指标归一化。`profile_nsys.py` 只读取官方
导出的 SQLite/表结构，不解析私有 `.nsys-rep`。`profile_pytorch.py` 只读取经过版本和字段
校验的 Chrome trace。支持的 dialect 由对应 fixture 和官方版本证据固定，新增版本必须先加
一个失败 fixture。

编译器和 SASS 也使用相同的 Invocation 生命期，但只提供 `analyze`。编译器读取显式指定的
阶段产物；SASS 对显式 binary 运行受控反汇编命令。两者都不负责触发 workload 构建或选择
需要分析的 kernel。

`execution_map.py` 只计算已知 observation 的时间覆盖、重叠和可核验上限，不输出瓶颈名称。

### 4.8 知识与安装检查

`knowledge_query.py` 合并 `capability_query.py` 的安全来源校验、`diagnostic_knowledge.py` 的
身份过滤以及现有简单查询。最终只保留一套知识数据：

```text
references/knowledge/cards.json
references/knowledge/sources.json
references/knowledge/playbooks/*.md
```

现有 capability、diagnostic、method、workload 和 case 内容先按 id、来源和机制去重后迁入，
不因当前 5090 案例删掉其它架构或 workload 层内容。query 有结果数量和上下文字节上限。

`self_check.py` 只检查：

- 17 个最终生产模块完整且没有额外入口；
- 依赖方向无环；
- driver schema；
- 知识文件摘要和来源闭合；
- 安装级 runtime 锁配置可读取；
- 旧 Controller、旧 schema 和旧入口不存在。

`version_audit.py` 保留为 readiness、Profiler 和 self-check 复用的只读版本、来源校验模块。
它不写 artifact、不启动命令，也不形成独立优化流程。

|---|---|
| `target.json`、original object | `readiness.py check` |
| `experiments/<id>.json`、candidate object | `workload_evaluate.py experiment` |

## 6. Operation 调用链

以下顺序是实现时的实际调用链。箭头后的失败结果表示本次 operation 终止；后续步骤不得启动。

### 6.1 `readiness check`

```text
封闭字段和授权检查
→ artifact 父目录原子语义检查
→ 有界扫描并在临时目录冻结 original
→ adapter 校验 driver
→ runtime probe 执行低成本 smoke
→ 校验 smoke 输出和 cleanup
→ 构造 Target
→ 把完整临时 artifact root 原子发布到目标路径
```

- 任一步失败：删除临时内容，不创建 artifact root 或 Invocation。
- smoke 需要 GPU：probe guardian 取得共享锁并在返回前清理。
- diagnostic Target：不伪造 driver 或 smoke，只冻结已有报告、original 和环境身份。

### 6.2 `baseline`

```text
前台校验 optimization Target 和 request
→ runtime 去重并启动 worker
→ 隔离物化 original
→ separate: correctness
   → 失败：写 invalid/failed result，跳过 measure
   → 通过：measure
→ combined: 运行一次并先解释 correctness
   → 失败：保留诊断样本但不得形成 baseline
→ 校验指标、单位、样本和 cleanup
→ 写 baseline result
```

baseline 不创建 Experiment，不运行 Profiler，不生成方向。

### 6.3 `experiment`

```text
校验 Target
→ 校验 original baseline
→ 读取当前 Champion
→ 有界冻结 source base 和 candidate
→ 计算实际 diff
→ 校验 change_scope、max_risk 和三个 Variant 身份
→ 校验 falsifier、screen、成本和通过/拒绝条件
→ create-once 写 Experiment
```

这是同步元数据动作，不创建 Invocation、不取得 GPU 锁、不执行候选命令。任一步失败时不留下
半份 Experiment 或 candidate object。

### 6.4 `screen`

```text
前台校验 Experiment、baseline 和当前 reference
→ runtime 启动 worker
→ 隔离物化 candidate
→ 再核对 reference
→ candidate correctness
   → 失败：跳过性能
→ separate driver 在性能前再次核对 reference
   → 已过期：保留正确性，跳过性能
→ 可选短版配对测量
→ 根据 Experiment 已冻结的 screen 条件写 verdict
```

源码静态审查和独立小测试在创建 Experiment 前由 ChatGPT 完成，不属于 `screen` 内部步骤。

### 6.5 `target`

```text
前台校验 Experiment、baseline、screen 门禁和当前 reference
→ runtime 启动 worker
→ 取得所需共享资源
→ 再核对 reference
   → 已过期：不启动 workload
→ candidate correctness
   → 失败：跳过性能
→ reference correctness
   → 失败：跳过性能
→ separate driver 在性能前再次核对 reference
   → 已过期：跳过性能
→ candidate 与 reference 正式配对
→ 校验约束、统计和 cleanup
→ 写正式比较 result
```

已有正确性 receipt 只有在内容、Target、case、环境和有效期要求完全相同时才能复用。工具不因
结果通过而调用 `champion select`。

### 6.6 `final_audit`

```text
读取当前 Champion Selection
→ 冻结 original、Champion 和 selection reference 到 request
→ runtime 启动 worker并取得资源
→ 再核对 selection
→ 本次重新执行 original correctness
→ 本次重新执行 Champion correctness
→ 性能前再次核对 selection
→ original 与 Champion 正式配对
→ 写 audit result
```

Selection 过期、任一侧正确性失败或结果无效时，不能发布最终收益。工具只写事实；由 ChatGPT
决定停止、重试或显式恢复 original。

### 6.7 `champion`

```text
show:
  校验 Target → 读取 current；不存在时返回 original

select:
  校验普通 target result
  → 核对 result.reference == current
  → create-once 写 Selection
  → CAS current

restore-original:
  校验 final_audit 及其 current binding
  → create-once 写恢复 Selection
  → CAS current
```

CAS 失败只报告 stale reference，不自动重测或选择其它结果。

### 6.8 Profiler、编译器和 SASS

```text
analyze:
  校验 Target、报告引用、工具版本和 dialect
  → runtime 启动只读 worker
  → 解析已冻结材料
  → 未知版本/关键字段/单位时整次 invalid；非关键扩展写入 unmodeled
  → 写 observations、unmodeled 和 provenance

collect:
  校验 Target 和 baseline
  → candidate 还需 Experiment 与正确性 receipt
  → adapter 构造同一 driver argv
  → runtime guardian 取得资源并运行 profiler 包装后的 argv
  → 校验原始报告和 cleanup
  → 按已知 dialect 提取事实
```

编译器和 SASS 没有 `collect`；它们只分析显式产物，不触发构建。

### 6.9 `knowledge query`

```text
封闭字段校验
→ 读取并核对本地知识来源摘要
→ 按硬件、软件、现象和结论层级过滤
→ 按机制 id 去重
→ 应用数量和上下文字节上限
→ 返回卡片或空列表
```

不创建 Invocation，不访问外网，不运行命令。

## 11. 实施停止条件

出现下列情况时停止当前批次，不做局部补丁：

- runtime 需要理解候选、Champion、ROI 或下一步；
- evaluator 开始选择方向或自动启动 Profiler；
- adapter 又出现第二套子进程运行逻辑；
- 为兼容旧测试恢复 Controller 私有接口；
- 新增全局状态、checkpoint 或流程恢复镜像；
- 同一业务记录出现第二写入者；
- 需要新增第 18 个生产模块；
- 新代码超过同批删除代码；
- 黑盒测试只能通过修改用户 workload 或放宽有效性要求；
- 一个完整人工决策路径无法由公开工具逐项完成。

停止后先用调用链和记录所有权定位边界错误。只有用户改变产品目标，才重新讨论 V1.4 的核心
抽象。
