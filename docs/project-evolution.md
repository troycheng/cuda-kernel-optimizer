# 项目如何从真实使用中改进

[English](project-evolution.en.md)

## 这套方法解决什么问题

真实优化任务会暴露项目自身的问题：指令不够清楚、工具漏掉非法输入、知识适用范围不准，或者一次操作花费了没有必要的时间。单个案例可以指出问题，却不能自动证明一条通用规则。

本项目采用一条简单做法：任务结束后，由人决定是否整理案例；范围明确的项目修改完成后，先固定比较条件，再运行评测；事实写入结果，最后由维护者决定是否发布。这样既能从真实使用中改进，也能说明每项改动的依据和适用范围。

## 不会发生什么

- skill 不会在优化过程中改写自己；
- 项目不收集或上传用户的 private workload、内部 trace、权重、专有源码或业务数据；
- 案例不会自动进入知识库；
- 评测结果不自动合并，也不自动发布；
- 这套维护方法不修改 V1.4 运行时。

V1.4 的分工保持不变：ChatGPT 负责优化判断，确定性工具一次只执行一项明确操作并记录事实。项目演进发生在一次优化任务结束之后，不干预任务内部怎样分析和实验。

## 六项要素分别做什么

| 要素 | 作用 | 在仓库中的表示 |
|---|---|---|
| 演进契约（Evolution Contract） | 固定长期不应被一次评测改写的边界 | 已确认的[完整设计](maintenance/evidence-driven-self-evolution-design.md) |
| 案例快照（Case Snapshot） | 保存原始问题，同时把挑战材料与历史答案分开 | `case-snapshot.md` |
| 项目版本（Project Revision） | 准确说明仓库改了什么 | Git commit 或 tag |
| 评测定义（Evaluation Definition） | 在结果出现前固定比较对象、环境、方法和结论上限 | `evaluation-definition.md` |
| 评测结果（Evaluation Result） | 只记录实际身份、测量、失败、成本和不确定性 | `evaluation-result.md` |
| 发布决定（Release Decision） | 由维护者说明采用、拒绝、收窄、撤回或回滚 | `release-decision.md` 与实际 release 记录 |

六项要素不构成新的执行系统。它们只保存依据和责任，没有任何一项会调用下一项。

## 一次贡献怎样完成

```text
真实任务暴露问题
  → 人决定是否整理公开案例
  → 提出范围明确的仓库修改
  → 在结果产生前提交评测定义
  → 运行独立评测并记录事实
  → 人审查并决定是否发布
```

普通、范围明确的代码修复仍然可以直接提交。只有改动 ChatGPT 行为、知识适用范围、评测方法或公开性能结论时，才需要完整的项目演进材料。

## 哪些内容适合贡献

- 可公开的最小复现和确定性工具缺陷；
- GPU、CUDA、框架或 Profiler 的兼容边界；
- 能独立运行的测试、代码和文档修正；
- 具有公开 workload、精度校验、原始基线和环境身份的性能案例；
- 根据私有实践重新构造、可以公开验证的合成案例。

公开案例一旦发布，就适合作为示例和回归材料，不再是保留案例。多个来源相同的重复提交也不会自动增加结论可信度。

## 私有实践怎样帮助项目

私有材料留在用户自己的环境。贡献者可以说明问题来自哪类环境，并提交一个公开最小复现、测试、代码修复或适用范围修订。删去“内部验证过”这句话后，公开改动仍必须依靠公开材料成立。

私有声明只能解释为什么提出修改，不能证明生产性能、正确性或通用性。社区代码和附件也不会自动在项目维护者的 GPU 上运行。

## 需要多少证据

确定性工具和协议使用一致性评测：一个真实复现、正常与非法输入、fail-closed 检查和对应回归通常足以支持一项范围明确的修复。

ChatGPT 指令、知识和方向判断使用行为评测：固定模型、环境和授权，在干净会话中重复运行，并加入反例或保留案例。评测看语义结果是否正确，不要求复刻历史任务中的每条命令。

局部证据只支持局部声明。一个工具修复不能证明性能提升；一个真实任务也不能证明对所有 GPU workload 普遍有效。

## 模板和示例

四个模板位于仓库的 [`.github/evolution`](https://github.com/troycheng/cuda-kernel-optimizer/tree/main/.github/evolution) 目录：`case-snapshot.md`、`evaluation-definition.md`、`evaluation-result.md` 和 `release-decision.md`。贡献入口跟随主仓库更新，不随已安装 skill 进入用户项目。

首个公开示例是一次 [Profiler 证据对象校验修复](evolution-case-profiler-evidence-validation.md)。它展示怎样回放确定性工具缺陷，也明确说明回溯证据不能支持哪些结论。
